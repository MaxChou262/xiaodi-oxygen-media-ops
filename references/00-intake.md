# 输入与建档

## 三个输入

经销商的标准句式是：

```
@小狄氧舱自媒体平台运营智能体 杭州 GYCHA-M001 本周同城和全国康养热点，出10个能拍的
```

| 输入 | 为什么必须 | 缺了怎么办 |
|---|---|---|
| 城市 | 本地热点是这套东西唯一的差异化，猜一个整份都废 | 必须问，不给默认值 |
| 型号 | 决定讲"私密"还是"翻台"，讲错就露怯 | 问一次；仍不答按 GYCHA-M001，标注「按双人舱假设」 |
| 需求 | 默认「本周热点＋10 条脚本」 | 不问，直接按默认走 |

**最多问一轮，三个一起问。** 只缺城市时，只问城市。

## 经销商分型

建档时判断，决定选题配比微调。

| 型 | 特征 | 配比微调 |
|---|---|---|
| A 已装舱有客户 | 有现场、有客人、能拍实证 | 体验/场景类 +1，可拍客户出镜 |
| B 有样机没客户 | 只有机器和场地 | 避坑类 +1，实证用公开案例替代，绝不写"我们客户都说好" |
| C 还在找场地 | 没场地、没机器 | 全部走"这门生意值不值得做"，不拍产品细节 |

C 型最容易犯的错：照抄 A 型的脚本，满屏参数、零可信度。

## 档案文件

存 `dealers/<城市>-<型号>.md`。第二次接触先读文件，只问变化的那一项。

```markdown
# <城市>-<型号>

| 项 | 内容 |
|---|---|
| 城市／位置 | |
| 场地形态 | 门店／会所／康养中心／健身房／酒店／自有别墅／找场地中 |
| 型号 | GYCHA-S001 / M001 / M002 / GYCHC-M001 |
| 出镜人 | 老板／店长／工程师／无人出镜 |
| 分型 | A / B / C |
| 每周拍摄时间 | |
| 建档日期 / 最近更新 | |

## 已发记录
| 日期 | 标题 | 挂了哪条热点 | 播放 | 完播 | 关注 | 私信 |

## 拍不了的（留着，条件变了能复活）
| 选题 | 缺什么 | 日期 |
```

## 记录纪律

- 每次出稿回写一行：标题、挂的热点、发布时间。数据有了再补。
- 拍不了的不要删，标原因。素材条件一变它就活了。
- 三次没用上的选题，标「已死」，换新的。
